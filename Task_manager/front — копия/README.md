# Task Manager — документация

Учебное веб-приложение для планирования задач по дням, неделям и месяцам. Написано на **Vue 3** (Composition API, `<script setup>`) и **Vue Router**. Данные хранятся в `localStorage`, слой хранения изолирован и рассчитан на последующую замену бэкендом.

## 1. Возможности и соответствие заданию

| Требование задания | Как реализовано |
|---|---|
| Список задач по дням недели, навигация по неделям вперёд и назад | Страница `/week/:date`: 7 колонок (Пн–Вс), кнопки «← Пред.», «След. →», «Сегодня» |
| Задачи каждого дня видны как в календаре, одна неделя на странице | Компонент `DayColumn` для каждого дня, на мобильных колонки встают вертикально |
| Выбор дня и открытие его на отдельной странице | Клик по колонке дня ведёт на `/day/:date` |
| Минимум 3 месяца | Страница `/month/:ym` показывает три месяца одновременно: предыдущий, текущий, следующий. Окно сдвигается на месяц вперёд/назад без ограничений |
| Цель на месяц и на год | `GoalEditor` под заголовком каждого месяца и общий блок цели года |
| Фильтрация | По приоритету и статусу (общие для недели, дня и месяцев) |
| Поиск | По названию и описанию, без учёта регистра |
| Создание, редактирование, удаление | Форма и список на странице дня, удаление с подтверждением |
| Статусы и приоритеты задач | Статусы: «К выполнению», «В работе», «Выполнена». Приоритеты: низкий, средний, высокий. Отображаются бейджами и цветом |

Дополнительно:
- статистика недели и дня с полосой прогресса;
- перенос задачи на другой день через поле даты в форме;
- синхронизация между вкладками браузера;
- автоматическая миграция данных старой версии приложения;
- валидация дат и месяцев в URL.

## 2. Технологии

- **Vue 3** — Composition API, `<script setup>`
- **Vue Router 4** — страницы, навигация, параметры в URL
- **Vite** — сборка и dev-сервер
- **localStorage** — хранение данных (временное решение)
- Чистый CSS (scoped-стили в компонентах), без UI-библиотек

Pinia не используется: общее состояние реализовано через composables с состоянием на уровне модуля (см. раздел 5).

## 3. Установка и запуск

Требуется Node.js 18+.

```bash
cd front
npm install
npm install vue-router     # если ещё не установлен
npm run dev                # режим разработки
npm run build              # production-сборка
npm run preview            # просмотр production-сборки
```

Все команды выполняются из корня фронтенд-проекта (папка с `package.json`), а не из `src`.

## 5. Архитектура

### 5.1 Слои

```
┌──────────────────────────────────────────┐
│  views/        страницы, привязаны к URL │
├──────────────────────────────────────────┤
│  components/   отображение и события     │
├──────────────────────────────────────────┤
│  composables/  состояние + бизнес-логика │
├──────────────────────────────────────────┤
│  api/storage   хранение данных           │
├──────────────────────────────────────────┤
│  localStorage  (позже — HTTP-бэкенд)     │
└──────────────────────────────────────────┘
```

Правила зависимостей: каждый слой знает только о слое ниже. Компоненты не обращаются к `localStorage` напрямую. Благодаря этому замена хранилища затрагивает один файл (`api/storage.js`).

### 5.2 Общее состояние без Pinia

В `useTasks.js` и `useGoals.js` реактивные переменные (`tasks`, `filters`, `goals`) объявлены **на уровне модуля**, а не внутри функции `useTasks()`. Модуль в JavaScript загружается один раз, поэтому все вызовы `useTasks()` из разных страниц получают одни и те же данные. Это даёт то же, что общий store: изменения в `DayView` сразу видны в `WeekView` и `MonthsView`.

### 5.3 Поток данных

```
Действие пользователя (клик, ввод)
        ↓
Компонент → emit события / вызов функции composable
        ↓
useTasks: addTask / updateTask / deleteTask
        ↓
api/storage.js: запись в localStorage → возвращает сохранённый объект
        ↓
useTasks: обновляет реактивный массив tasks
        ↓
Vue перерисовывает все computed и компоненты, зависящие от tasks
```

Данные сначала сохраняются, и только потом обновляется состояние, поэтому интерфейс показывает то, что реально записано.

### 5.4 Инициализация

В `main.js` до монтирования приложения вызываются `initTasks()` и `initGoals()`: они асинхронно читают данные из хранилища и подписываются на событие `storage` (изменения из других вкладок). Повторные вызовы безопасны: загрузка выполняется один раз.

## 6. Модель данных

### 6.1 Задача

```js
{
  id: 'b6f0...',              // строка, crypto.randomUUID()
  title: 'Написать отчёт',    // обязательное, не пустое
  description: '',            // необязательное
  priority: 'medium',         // 'low' | 'medium' | 'high'
  status: 'todo',             // 'todo' | 'in_progress' | 'done'
  date: '2026-10-19',         // день задачи, YYYY-MM-DD
  createdAt: '2026-10-19T08:30:00.000Z',   // ISO-строка, не меняется
  updatedAt: '2026-10-19T09:00:00.000Z'    // обновляется при каждом изменении
}
```

### 6.2 Цели

```js
{
  months: { '2026-10': 'Закончить курсовую' },   // ключ — YYYY-MM
  years:  { '2026': 'Выучить Vue' }              // ключ — YYYY
}
```

Пустой текст при сохранении удаляет запись.

### 6.3 Ключи localStorage

| Ключ | Содержимое |
|---|---|
| `task-manager:tasks` | массив задач |
| `task-manager:goals` | объект целей |
| `task-manager:schema` | версия схемы данных (сейчас `2`) |

### 6.4 Формат дат

Везде в состоянии, URL и хранилище даты — **строки**: день `YYYY-MM-DD`, месяц `YYYY-MM`. Объекты `Date` создаются только внутри функций `utils/date.js` на время вычислений. Это исключает ошибки часовых поясов: стандартный `toISOString()` работает по UTC и в часовых поясах восточнее Гринвича (например, Алматы, UTC+5) ночью может дать вчерашнюю дату. Функция `toISO` берёт локальные год, месяц и день.

Неделя начинается с понедельника.

### 6.5 Миграция

Версия 1 хранила задачи с полем `completed` (boolean) и без даты задачи. При первом запуске новой версии функция `migrate()` в `storage.js`:

- заменяет `completed` на `status` (`true` → `'done'`, `false` → `'todo'`);
- добавляет `date`, беря её из `createdAt`;
- приводит `id` к строке, добавляет `updatedAt`, подставляет значения по умолчанию для некорректных полей;
- записывает `schema = 2`, чтобы миграция не выполнялась повторно.

Для будущих изменений структуры достаточно повысить `SCHEMA_VERSION` и добавить шаг в `migrate()`.

## 7. Маршруты

| Путь | Имя | Страница | Описание |
|---|---|---|---|
| `/` | — | редирект | на `/week/<сегодня>` |
| `/week/:date` | `week` | `WeekView` | неделя, содержащая дату `date` |
| `/day/:date` | `day` | `DayView` | один день |
| `/month` | — | редирект | на `/month/<текущий месяц>` |
| `/month/:ym` | `month` | `MonthsView` | три месяца; `ym` — центральный |
| любой другой | — | редирект | на `/` |

Примеры: `/week/2026-10-19`, `/day/2026-10-21`, `/month/2026-10` (покажет сентябрь, октябрь, ноябрь).

**Защита от невалидных значений.** Глобальный `router.beforeEach` проверяет `:date` (`isValidISO`) и `:ym` (`isValidMonth`). Некорректное значение (`/week/abc`, `/day/2026-02-31`, `/month/2026-13`) перенаправляет на `/`. Использован именно `beforeEach`, а не `beforeEnter`, потому что он срабатывает и при смене параметра на той же странице.

**Ленивая загрузка.** Страницы подключаются через `() => import(...)`, поэтому код страницы загружается только при первом переходе.

**Подсветка вкладок** в `App.vue` определяется по имени маршрута (`route.name`), а не по параметрам, иначе вкладка «Неделя» гасла бы на любой неделе, кроме текущей.

## 8. Справочник модулей

### 8.1 `constants.js`

| Экспорт | Описание |
|---|---|
| `PRIORITIES` | `[{ value, label }]` — низкий, средний, высокий |
| `STATUSES` | `[{ value, label }]` — todo, in_progress, done |
| `PRIORITY_ORDER` | `{ high: 0, medium: 1, low: 2 }` — для сортировки |
| `PRIORITY_VALUES`, `STATUS_VALUES` | массивы допустимых значений (для валидации) |

### 8.2 `utils/date.js`

Все функции чистые. `iso` — строка `YYYY-MM-DD`, `ym` — `YYYY-MM`.

| Функция | Возвращает |
|---|---|
| `toISO(date)` | `Date` → `'YYYY-MM-DD'` по локальному времени |
| `fromISO(iso)` | `'YYYY-MM-DD'` → `Date` (локальная полночь) |
| `today()` | сегодняшняя дата строкой |
| `monthKey(iso)` | `'2026-10-19'` → `'2026-10'` |
| `isValidISO(iso)` | `true`, если дата существует (отсекает `2026-02-31`) |
| `isValidMonth(ym)` | `true` для `YYYY-MM` с месяцем 01–12 |
| `addDays(iso, n)` | дата ± n дней |
| `addWeeks(iso, n)` | дата ± n недель |
| `addMonths(ym, n)` | месяц ± n месяцев (корректно переходит через год) |
| `startOfWeek(iso)` | понедельник той недели |
| `getWeekDays(iso)` | массив из 7 дат недели (Пн–Вс) |
| `getMonthGrid(ym)` | массив недель; каждая — 7 объектов `{ date, inMonth }`. Дни соседних месяцев имеют `inMonth: false` |
| `formatDay(iso)` | «пн, 19 окт.» |
| `formatDayFull(iso)` | «понедельник, 19 октября 2026 г.» |
| `formatMonth(ym)` | «октябрь 2026 г.» |
| `formatWeekRange(iso)` | «19 окт. — 25 окт.» |

### 8.3 `api/storage.js` — контракт репозитория

Все методы асинхронные, чтобы позже заменить реализацию на `fetch` без изменения вызывающего кода.

| Метод | Описание |
|---|---|
| `getTasks()` | вернуть все задачи |
| `createTask(data)` | создать задачу (генерирует `id`, `createdAt`, `updatedAt`, по умолчанию `status: 'todo'`), вернуть её |
| `updateTask(id, patch)` | применить частичные изменения, обновить `updatedAt`, вернуть задачу; ошибка, если `id` не найден |
| `deleteTask(id)` | удалить задачу |
| `getGoals()` | вернуть `{ months, years }` |
| `saveGoal(type, key, text)` | `type` — `'months'` или `'years'`; пустой текст удаляет цель; возвращает все цели |
| `subscribe(onChange)` | подписка на изменения из других вкладок; возвращает функцию отписки. Колбэк получает `'tasks'` или `'goals'` |
| `normalizeTask(raw)` | привести произвольный объект к актуальной схеме задачи |

Любая реализация (localStorage, REST и т. д.) должна сохранять эти сигнатуры.

### 8.4 `composables/useTasks.js`

`initTasks()` — однократная загрузка и подписка на другие вкладки.

`useTasks()` возвращает:

| Имя | Тип | Описание |
|---|---|---|
| `tasks` | `ref<Task[]>` | все задачи |
| `loading` | `ref<boolean>` | идёт начальная загрузка |
| `error` | `ref<Error \| null>` | последняя ошибка операции |
| `filters` | `reactive` | `{ search, priority, status }` — общие для всех страниц |
| `tasksForDate(date, { filtered = true })` | функция | задачи дня, отсортированные по приоритету (высокий первым), затем по времени создания. С `filtered: false` фильтры не применяются |
| `tasksForDates(dates, opts)` | функция | то же для массива дат; результат — объект `{ date: Task[] }` |
| `getStats(list)` | функция | `{ total, todo, inProgress, done, progress }`, `progress` — процент выполненных |
| `resetFilters()` | функция | сбросить поиск и фильтры |
| `addTask(data)` | async | создать задачу |
| `updateTask(id, patch)` | async | изменить поля |
| `deleteTask(id)` | async | удалить |
| `setStatus(id, status)` | async | сменить статус |
| `setPriority(id, priority)` | async | сменить приоритет |
| `moveToDate(id, date)` | async | перенести на другой день |

`tasksForDate` можно вызывать внутри `computed`: зависимость от `tasks` и `filters` отслеживается автоматически.

**Логика фильтрации** (`matches`): задача проходит, если одновременно выполнены три условия — поисковая строка (после `trim` и перевода в нижний регистр) входит в название или описание; приоритет совпадает или выбран «все»; статус совпадает или выбран «все».

### 8.5 `composables/useGoals.js`

`initGoals()` — загрузка и подписка. `useGoals()` возвращает:

| Имя | Описание |
|---|---|
| `goals` | `ref<{ months, years }>` |
| `getMonthGoal(ym)` | текст цели месяца или `''` |
| `getYearGoal(year)` | текст цели года или `''` |
| `setMonthGoal(ym, text)` | сохранить (пустой текст удаляет) |
| `setYearGoal(year, text)` | сохранить (пустой текст удаляет) |

### 8.6 `seed.js`

`seedDemoData(startMonth = '2026-10', months = 3)` — создаёт 0–3 задачи в каждый день указанных месяцев, разные приоритеты и статусы, цель на каждый месяц и на год. Если задачи уже есть, ничего не делает.

## 9. Справочник компонентов

### 9.1 Базовые

**`BaseButton`**

| Prop | Тип | По умолчанию |
|---|---|---|
| `variant` | `'primary' \| 'danger' \| 'success' \| 'secondary'` | `'primary'` |

Атрибуты `type`, `disabled` и обработчики `@click` пробрасываются на корневой `<button>` автоматически (fallthrough-атрибуты), отдельно объявлять их не нужно.

**`BaseCard`** — слоты `header` (необязательный), по умолчанию (тело) и `footer` (необязательный). Секции `header` и `footer` отрисовываются, только если слот передан. Классы, добавленные снаружи, попадают на корневой `<div>`.

`BaseButton` и `BaseCard` зарегистрированы **глобально** в `main.js`, поэтому их не нужно импортировать в каждом компоненте.

### 9.2 Страницы

**`WeekView`** — читает `route.params.date`, вычисляет 7 дней недели и задачи каждого дня (с фильтрами). Показывает статистику недели (без учёта фильтров), фильтры и сетку `DayColumn`.

**`DayView`** — страница дня. Хранит `editingTask` (редактируемая задача или `null`). Показывает навигацию по дням, статистику дня, `TaskForm`, `TaskFilters` и список `TaskItem`. При смене дня режим редактирования сбрасывается. Удаление запрашивает подтверждение через `confirm`.

**`MonthsView`** — вычисляет три месяца вокруг `route.params.ym`, одним `computed` собирает задачи всех их дней, показывает цель года (для года центрального месяца), фильтры и три `MonthCalendar`.

### 9.3 Компоненты

| Компонент | Props | Events |
|---|---|---|
| `DayColumn` | `date` (String, обяз.), `tasks` (Array), `isToday` (Boolean) | `open(date)` |
| `MonthCalendar` | `ym` (String, обяз.), `tasksByDate` (Object), `todayISO` (String, обяз.), `isCurrent` (Boolean) | `open(date)` |
| `GoalEditor` | `modelValue` (String), `label` (String, обяз.), `placeholder` (String) | `save(text)` |
| `TaskForm` | `editingTask` (Object \| null), `defaultDate` (String, обяз.) | `submit({ title, description, priority, date })`, `cancel` |
| `TaskItem` | `task` (Object, обяз.) | `edit(task)`, `delete(id)`, `change-status(id, status)`, `change-priority(id, priority)` |
| `TaskFilters` | `search`, `priority`, `status` (String) | `update:search`, `update:priority`, `update:status`, `reset` |
| `TaskStats` | `stats` (`{ total, todo, inProgress, done, progress }`), `title` (String) | — |

Особенности:

- **`TaskForm`** заполняется данными задачи при выборе на редактирование (`watch` по `editingTask`) и очищается при сбросе. Кнопка отправки неактивна, пока пусто название или дата. При редактировании статус не передаётся, поэтому сохраняется прежний.
- **`TaskFilters`** используется с `v-model:search`, `v-model:priority`, `v-model:status`, привязанными к общему объекту `filters`. Кнопка «Сбросить» видна только при активных фильтрах.
- **`MonthCalendar`** для каждого дня показывает число и значок с количеством задач. Цвет значка и фона — по самому высокому приоритету среди задач дня; если все задачи выполнены, клетка бледнеет; сегодняшний день обведён. Дни соседних месяцев не отрисовываются, чтобы не дублировать клетки.
- **`GoalEditor`** — режим просмотра и режим редактирования. `Ctrl+Enter` сохраняет, `Esc` отменяет.

## 10. Ключевые сценарии

**Создание задачи.** На `/day/:date` пользователь заполняет форму (дата по умолчанию — текущий день страницы) → `TaskForm` вызывает `emit('submit')` → `DayView.handleSubmit` → `addTask` → `storage.createTask` записывает задачу → она добавляется в начало массива `tasks` → список, статистика, неделя и месяцы обновляются автоматически.

**Редактирование.** Кнопка «Изменить» в `TaskItem` → `DayView` кладёт задачу в `editingTask` → форма заполняется → после сохранения вызывается `updateTask`, режим редактирования сбрасывается.

**Перенос на другой день.** В форме редактирования меняется поле даты. После сохранения задача пропадает из текущего дня и появляется на новой дате.

**Быстрая смена статуса.** В `TaskItem` — выпадающий список статуса или кнопка «Выполнить / Вернуть» (переключает `done` ↔ `todo`).

**Поиск и фильтры.** Состояние `filters` общее: введённый поиск сохраняется при переходе между неделей, днём и месяцами. Статистика недели и дня считается по всем задачам периода и от фильтров не зависит. На месячном экране значки показывают только подходящие под фильтр задачи.

**Синхронизация вкладок.** При изменении данных в одной вкладке браузер отправляет событие `storage` в остальные; `subscribe` перечитывает данные из хранилища и обновляет состояние.

**Навигация.** Все переходы выполняются через `router.push`, а значит работают кнопки браузера «назад/вперёд», закладки и прямые ссылки.

## 12. Принятые решения

| Решение | Причина |
|---|---|
| Репозиторий `api/storage.js` с async-методами | Переход на бэкенд сводится к замене одного файла |
| Состояние на уровне модуля вместо Pinia | Задание требует только Vue Router; для данного объёма этого достаточно |
| Даты как строки `YYYY-MM-DD` | Нет проблем с часовыми поясами, дату можно сравнивать как строку, удобно в URL |
| Статус как перечисление вместо `completed` | В задании требуется отображать статусы, boolean этого не позволяет |
| Фильтры общие для всех страниц | Единое поведение, поиск сохраняется при навигации |
| Статистика не зависит от фильтров | Числа показывают реальную картину периода, а не результат поиска |
| `id` через `crypto.randomUUID()` | Исключает коллизии, которые возможны при `Date.now()` при быстром создании |
| Окно из 3 месяцев сдвигается на один месяц | Сохраняет смысл «предыдущий — текущий — следующий» на каждом шаге |
| Цель года — по году центрального месяца | Простое и предсказуемое правило при пересечении границы года |
| Глобальная регистрация `BaseButton`, `BaseCard` | Они используются почти везде |

---

## 13. Известные ограничения

- **Хранение только в браузере.** Данные привязаны к конкретному браузеру и профилю; очистка данных сайта удалит всё. Объём `localStorage` ограничен (около 5 МБ).
- **`crypto.randomUUID()`** доступен только в безопасном контексте: `localhost` или HTTPS. При открытии dev-сервера по IP-адресу локальной сети через HTTP (`http://192.168...`) создание задач не сработает.
- **Ошибки операций** сохраняются в `error`, но пока не показываются пользователю.
- **Просроченные задачи** не выделяются.
- **Нет drag-and-drop** для переноса задач между днями; перенос выполняется через форму.
- **Нет автотестов.** Чистые функции (`utils/date.js`, `getStats`, `matches`) легко покрываются модульными тестами.
- **Неделя всегда с понедельника**, настройки нет.
- **Язык интерфейса** — только русский (даты форматируются через `ru-RU`).
- Цель года для окна на стыке годов показывается только для года центрального месяца.

## 14. Переход на бэкенд

Благодаря слою `api/storage.js` менять нужно только его. Компоненты и composables остаются прежними.

### 14.1 Рекомендуемое API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/tasks` | список задач |
| POST | `/tasks` | создать |
| PATCH | `/tasks/:id` | изменить |
| DELETE | `/tasks/:id` | удалить |
| GET | `/goals` | получить цели |
| PUT | `/goals/:type/:key` | сохранить цель (пустой текст — удалить) |

Для быстрого старта подойдёт `json-server`; для полноценного решения — Express/Fastify + база данных.

### 14.2 Пример замены `storage.js`

```js
const BASE = import.meta.env.VITE_API_URL ?? 'http://localhost:3000'

async function request(path, options = {}) {
  const res = await fetch(BASE + path, {
    headers: { 'Content-Type': 'application/json' },
    ...options
  })
  if (!res.ok) throw new Error(`HTTP ${res.status}: ${path}`)
  return res.status === 204 ? null : res.json()
}

export const getTasks = () => request('/tasks')
export const createTask = data =>
  request('/tasks', { method: 'POST', body: JSON.stringify(data) })
export const updateTask = (id, patch) =>
  request(`/tasks/${id}`, { method: 'PATCH', body: JSON.stringify(patch) })
export const deleteTask = id => request(`/tasks/${id}`, { method: 'DELETE' })

export const getGoals = () => request('/goals')
export const saveGoal = (type, key, text) =>
  request(`/goals/${type}/${key}`, { method: 'PUT', body: JSON.stringify({ text }) })

// Синхронизация между вкладками через localStorage больше не нужна.
// Позже можно заменить на WebSocket / периодический опрос.
export const subscribe = () => () => {}
```

### 14.3 Что ещё потребуется

1. Показ состояний `loading` и `error` в интерфейсе (они уже есть в `useTasks`).
2. Перенос `id` и меток времени на сервер (клиентская генерация `id` станет не нужна).
3. Одноразовый импорт существующих данных из `localStorage` на сервер.
4. При желании — оптимистичные обновления (сначала менять состояние, затем отправлять запрос, при ошибке откатывать).
5. Авторизация, если данные должны быть разными у разных пользователей.

## 15. Решение типичных проблем

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `does not provide an export named 'toISO'` | В `utils/date.js` лежит не тот код (например, содержимое `storage.js`) | Заменить содержимое `date.js` на правильную версию; файл должен начинаться с `const pad = ...` и `export const toISO` |
| `Failed to resolve import "../utils/date.js"` | Файл лежит не в той папке | Сверить структуру с разделом 4 |
| `Failed to resolve import "vue-router"` | Не установлен роутер | `npm install vue-router` в корне проекта |
| Пустая страница, в консоли `createApp is not defined` | Старая версия `main.js` | Заменить на актуальную |
| Старые компоненты работают со старой моделью (`completed`) | Не заменены `TaskItem`, `TaskForm`, `TaskStats`, `TaskFilters` | Использовать актуальные версии |
| `Unknown custom element: <BaseCard>` | Не зарегистрированы глобальные компоненты | Проверить `app.component(...)` в `main.js` |
| Календарь пустой | Нет данных | Создать задачу вручную или запустить `seedDemoData` (раздел 11) |
| `seedDemoData` ничего не делает | В хранилище уже есть задачи | Выполнить `localStorage.clear()` и обновить страницу |
| Задачи не создаются на локальной сети по IP | `crypto.randomUUID` недоступен вне HTTPS/localhost | Открывать через `localhost` или использовать HTTPS |
| Переход на `/week/abc` ведёт на главную | Так и должно быть: невалидные даты отсекаются | — |

Файлы, скачанные по одному, могут попадать в одну папку; перед запуском убедитесь, что каждый файл лежит на своём месте (разделы 4 и 15).
