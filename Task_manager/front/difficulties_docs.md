# Часть 1. Функции с алгоритмами и паттернами

## 1.1 `startOfWeek`: находим понедельник

```js
export function startOfWeek(iso) {
  const d = fromISO(iso)
  d.setDate(d.getDate() - ((d.getDay() + 6) % 7))
  return toISO(d)
}
```

`Date.getDay()` возвращает 0 для воскресенья, 1 для понедельника … 6 для субботы. Нам нужно, чтобы неделя начиналась с понедельника, то есть чтобы понедельник давал 0 («сколько дней назад был понедельник»). Формула `(день + 6) % 7` это делает:

| День | `getDay()` | `(d+6)%7` |
|---|---|---|
| Пн | 1 | 0 |
| Вт | 2 | 1 |
| Вс | 0 | 6 |

Дальше из даты вычитается это число дней. `setDate` с отрицательным или нулевым значением сам переходит в предыдущий месяц, поэтому ручной обработки границ не нужно.

## 1.2 `addMonths` и `addDays`: арифметика через нормализацию `Date`

```js
export function addMonths(ym, n) {
  const [y, m] = ym.split('-').map(Number)
  const d = new Date(y, m - 1 + n, 1)
  return `${d.getFullYear()}-${pad(d.getMonth() + 1)}`
}
```

Конструктор `Date` сам «заворачивает» переполнение: `new Date(2026, 12, 1)` (месяц 12 в нумерации с нуля) станет 1 января 2027. Поэтому декабрь + 1 месяц обрабатывается без `if`. 

Здесь день намеренно всегда равен `1`. Если бы мы брали, например, 31 января и прибавляли месяц, получили бы 3 марта (в феврале нет 31-го). Привязка к первому числу убирает эту проблему.

## 1.3 `isValidISO`: проверка «туда и обратно»

```js
export function isValidISO(iso) {
  if (!/^\d{4}-\d{2}-\d{2}$/.test(iso)) return false
  return toISO(fromISO(iso)) === iso
}
```

Регулярка проверяет только форму. Но `2026-02-31` по форме верна. Вторая строка преобразует её в `Date` (получится 3 марта), обратно в строку (`2026-03-03`) и сравнивает с исходной. Не совпало — такой даты не существует. Этот приём называется **round-trip validation**: проще и надёжнее, чем вручную считать количество дней в месяце и високосные годы.

## 1.4 `getMonthGrid`: построение сетки месяца (главный алгоритм)

```js
export function getMonthGrid(ym) {
  const first = `${ym}-01`
  const last = addDays(`${addMonths(ym, 1)}-01`, -1)   // последний день месяца
  const weeks = []
  let cursor = startOfWeek(first)
  while (cursor <= last) {
    weeks.push(getWeekDays(cursor).map(date => ({ date, inMonth: monthKey(date) === ym })))
    cursor = addDays(cursor, 7)
  }
  return weeks
}
```

Идея: календарь месяца это набор **полных недель**, которые покрывают месяц.

1. Последний день: берём первое число следующего месяца и отнимаем один день. Так не нужно знать, сколько дней в месяце.
2. Начинаем с понедельника недели, в которую попадает 1-е число (он может оказаться в предыдущем месяце).
3. Пока начало текущей недели не ушло за последний день месяца, добавляем неделю (7 дат) и сдвигаемся на 7 дней.
4. Дни соседних месяцев помечаются `inMonth: false`, чтобы их можно было скрыть.

Пример, октябрь 2026. 1 октября это четверг, значит, сетка начинается с 28 сентября. Недели: 28.09, 05.10, 12.10, 19.10, 26.10 (заканчивается 1 ноября). Следующая началась бы 2 ноября, это больше 31 октября, цикл завершается. Итого 5 недель по 7 клеток, из них 4 клетки в начале и 1 в конце «чужие».

Даты сравниваются **как строки** (`cursor <= last`). Это работает, потому что формат `YYYY-MM-DD` сортируется лексикографически так же, как хронологически.

## 1.5 Фильтрация и сортировка в `useTasks`

```js
function matches(task) {
  const q = filters.search.trim().toLowerCase()
  return (
    (!q || task.title.toLowerCase().includes(q) || task.description.toLowerCase().includes(q)) &&
    (filters.priority === 'all' || task.priority === filters.priority) &&
    (filters.status === 'all' || task.status === filters.status)
  )
}

const sortTasks = list =>
  [...list].sort((a, b) =>
    PRIORITY_ORDER[a.priority] - PRIORITY_ORDER[b.priority] ||
    a.createdAt.localeCompare(b.createdAt))
```

- **Конвейер условий.** Каждый фильтр это одно выражение «выключен ИЛИ совпадает», все три соединены через `&&`. Пустой поиск (`!q`) сразу даёт `true` и не вызывает остальное (короткое замыкание).
- **Составной компаратор.** `||` возвращает второй операнд, если первый равен `0`. То есть сначала сравниваются приоритеты, а при равенстве — время создания. Чем меньше число в `PRIORITY_ORDER`, тем выше приоритет (`high: 0`), поэтому важные задачи идут первыми.
- **`[...list]` перед `sort`.** `sort` изменяет массив на месте. Копия защищает от случайной мутации реактивных данных.

```js
function tasksForDates(dates, opts) {
  return Object.fromEntries(dates.map(d => [d, tasksForDate(d, opts)]))
}
```

Массив дат превращается в словарь `{ дата: [задачи] }`: `map` создаёт пары, `fromEntries` собирает объект. Этот словарь удобен для шаблонов: `byDay[d]`.

## 1.6 Паттерны в composables

**Одиночка на уровне модуля (module-level singleton).** `tasks`, `filters` и `goals` объявлены вне функции `useTasks()`. Модуль загружается один раз, поэтому все страницы разделяют одни данные. Это замена Pinia.

**Идемпотентная инициализация:**

```js
let initPromise = null
export function initTasks() {
  if (!initPromise) {
    initPromise = api.getTasks().then(...)
    api.subscribe(...)
  }
  return initPromise
}
```

Первый вызов запускает загрузку и запоминает промис, следующие возвращают тот же промис. Загрузка и подписка выполняются ровно один раз, сколько бы раз функцию ни вызвали.

**Обёртка `run`** (похожа на паттерн «декоратор»):

```js
async function run(fn) {
  error.value = null
  try { return await fn() }
  catch (e) { error.value = e; throw e }
}
```

Все операции (`addTask`, `updateTask`, `deleteTask`) проходят через неё, поэтому обработка ошибок написана один раз. Исключение пробрасывается дальше (`throw e`), чтобы вызывающий код мог на него отреагировать.

**Наблюдатель (Observer).** `subscribe(onChange)` в `storage.js` подписывается на событие `storage` браузера и возвращает функцию отписки. Это классический паттерн «подписка на изменения»: когда другая вкладка меняет данные, `useTasks` перечитывает их.

## 1.7 `api/storage.js`

**Репозиторий (Repository).** Все обращения к хранилищу скрыты за async-методами. Остальной код не знает, что внутри `localStorage`.

**Нормализация (`normalizeTask`).** Любой входящий объект приводится к актуальной схеме: некорректный приоритет заменяется на `medium`, из старого `completed` вычисляется `status`, отсутствующая дата берётся из `createdAt`. Одна функция работает и для миграции, и для создания, и для обновления.

**Чтение — изменение — запись (`updateTask`):**

```js
const updated = normalizeTask({
  ...list[index],            // старые поля
  ...patch,                  // новые поля
  id: list[index].id,        // защищённые поля
  createdAt: list[index].createdAt,
  updatedAt: new Date().toISOString()
})
```

Порядок в spread важен: поздние ключи перезаписывают ранние. `id` и `createdAt` ставятся после `patch`, поэтому их нельзя случайно перезаписать извне.

**Версионируемая миграция.** Ключ `task-manager:schema` хранит версию. Если версия меньше текущей, данные преобразуются один раз и версия обновляется. При следующем изменении структуры достаточно добавить шаг.

## 1.8 `MonthCalendar`: подготовка данных для клеток

```js
const topPriority = list =>
  list.reduce((best, t) =>
    PRIORITY_ORDER[t.priority] < PRIORITY_ORDER[best] ? t.priority : best,
    list[0].priority)

const weeks = computed(() =>
  getMonthGrid(props.ym).map(week =>
    week.map(cell => {
      const list = props.tasksByDate[cell.date] ?? []
      return { ...cell, day: Number(cell.date.slice(8)), count: list.length,
               priority: list.length ? topPriority(list) : null,
               allDone: list.length > 0 && list.every(t => t.status === 'done') }
    })))
```

- `reduce` ищет максимальный приоритет «по ходу»: сохраняет лучшего кандидата и заменяет его, если встретился с меньшим числом порядка.
- Вся информация (`count`, `priority`, `allDone`, номер дня) считается **один раз в `computed`**, а шаблон только читает готовые поля. Иначе пришлось бы вызывать функции прямо в шаблоне при каждой перерисовке.
- `?? []` защищает от дней без задач.

## 1.9 `MonthsView`: сбор данных трёх месяцев

```js
const byDate = computed(() => {
  const dates = months.value.flatMap(m =>
    getMonthGrid(m).flat().filter(c => c.inMonth).map(c => c.date))
  return tasksForDates(dates)
})
```

Цепочка: для каждого из трёх месяцев берём сетку → `flat()` разворачивает недели в один список клеток → `filter` оставляет только дни месяца → `map` берёт даты. `flatMap` склеивает результаты трёх месяцев в один массив. Затем один вызов даёт общий словарь, который передаётся всем трём календарям.

## 1.10 Router guard

```js
router.beforeEach(to => {
  if (to.params.date && !isValidISO(to.params.date)) return '/'
  if (to.params.ym && !isValidMonth(to.params.ym)) return '/'
})
```

Глобальный «страж»: возврат строки означает перенаправление, отсутствие возврата пропускает переход. Он срабатывает и при смене параметра на той же странице (например, когда вы листаете недели), чего не делает `beforeEnter`.

# Часть 2. Сложные шаблоны

## 2.1 Вложенные `v-for` в `MonthCalendar`

```vue
<div class="grid">
  <div v-for="w in WEEKDAYS" :key="w" class="grid__weekday">{{ w }}</div>

  <template v-for="(week, wi) in weeks" :key="wi">
    <template v-for="cell in week" :key="cell.date">
      <div v-if="!cell.inMonth" class="cell cell--empty" />
      <button v-else type="button" class="cell" ...>
```

Что здесь происходит:

1. **Первый цикл** создаёт 7 заголовков (Пн–Вс).
2. **Внешний `<template v-for>`** идёт по неделям, **внутренний** по дням недели.
3. **`<template>` не создаёт элемент в DOM.** Это принципиально: если бы каждую неделю обернули в `<div>`, то дочерними элементами `.grid` были бы 5–6 блоков-недель, а не 35–42 клетки, и CSS-сетка из 7 колонок не сработала бы. Через `<template>` все клетки становятся прямыми потомками `.grid` и раскладываются сеткой (подробнее в части 3).
4. **`:key` на `<template>`.** В Vue 3 ключ ставится на `<template v-for>`, а не на дочерние элементы. Для недель стоит индекс `wi`, для дней уникальная дата.
5. **`v-if` / `v-else` внутри цикла.** Чужие дни (`inMonth: false`) отрисовываются как пустая невидимая клетка, а не пропускаются. Пустышки нужны, чтобы 1-е число попало в правильную колонку: если месяц начинается в четверг, перед ним должны стоять три пустые клетки.

## 2.2 Составной `:class`

```vue
:class="[
  cell.priority && `cell--${cell.priority}`,
  { 'cell--today': cell.date === todayISO, 'cell--alldone': cell.allDone }
]"
```

Массив комбинирует разные формы записи: строку (динамический класс по приоритету) и объект (класс включается, если значение `true`). Значения `null`/`false` из массива просто игнорируются, поэтому у дня без задач класса приоритета не будет.

## 2.3 Именованные слоты (`BaseCard`)

```vue
<!-- BaseCard.vue -->
<header v-if="$slots.header" class="card__header"><slot name="header" /></header>
<div class="card__body"><slot /></div>
<footer v-if="$slots.footer" class="card__footer"><slot name="footer" /></footer>
```

```vue
<!-- TaskItem.vue -->
<BaseCard>
  <template #header>...</template>
  ...остальное содержимое — в тело...
  <template #footer>...</template>
</BaseCard>
```

Шапка и подвал рисуются только если родитель их передал (`$slots.header`). Так одна карточка подходит и для статистики (только шапка и тело), и для задачи (все три части).

Ещё одна деталь: когда в `TaskItem` пишут `<BaseCard :class="[...]">`, класс автоматически попадает на корневой `<div>` внутри `BaseCard`. Это работает потому, что у компонента один корневой элемент (fallthrough-атрибуты).

## 2.4 Пользовательский `v-model` с аргументами

```vue
<TaskFilters
  v-model:search="filters.search"
  v-model:priority="filters.priority"
  v-model:status="filters.status" />
```

Это сокращение для `:search="filters.search" @update:search="filters.search = $event"`. Внутри `TaskFilters` компонент получает значение как prop и сообщает об изменении через `emit('update:search', ...)`. Три независимых `v-model` на одном компоненте возможны именно благодаря аргументам (`:search`, `:priority`, `:status`). Привязка идёт к полям общего `reactive`-объекта `filters`, поэтому поиск сохраняется между страницами.

## 2.5 Два `watch` в `TaskForm`

```js
watch(() => props.editingTask, task => { /* заполнить или очистить */ }, { immediate: true })
watch(() => props.defaultDate, d => { if (!isEditing.value) form.date = d })
```

Первый следит за переключением режима. `immediate: true` запускает его сразу при создании компонента, чтобы форма сразу была в правильном состоянии. Второй подставляет новую дату, когда пользователь перешёл на другой день, но только если не идёт редактирование (иначе перезаписалась бы дата редактируемой задачи).

## 2.6 Доступная «кнопка» из `div` (`DayColumn`)

```vue
<div role="button" tabindex="0" @click="emit('open', date)" @keydown.enter="emit('open', date)">
```

Колонка содержит список, поэтому внутри неё нельзя использовать `<button>` (интерактивные элементы нельзя вкладывать друг в друга). `role="button"` и `tabindex="0"` дают доступность с клавиатуры, а `@keydown.enter` дублирует клик.

# Часть 3. CSS-сетка мини-календаря

```css
.grid {
  display: grid;
  grid-template-columns: repeat(7, minmax(0, 1fr));
  gap: 3px;
  margin-top: 12px;
}
.cell { position: relative; aspect-ratio: 1; padding: 0; border: 1px solid #e5e7eb; ... }
.cell__day   { position: absolute; top: 3px; left: 5px; }
.cell__badge { position: absolute; right: 3px; bottom: 3px; min-width: 16px; height: 16px; ... }
```

## 3.1 `repeat(7, minmax(0, 1fr))`: семь одинаковых колонок

- `repeat(7, ...)` создаёт 7 колонок (дни недели).
- `1fr` означает «одна доля свободного места». Но у `1fr` есть скрытый минимум: колонка не может стать уже своего содержимого (`min-content`). Если в клетке окажется длинный текст, колонка раздвинется, и сетка поплывёт.
- `minmax(0, 1fr)` убирает этот минимум: колонка может сжиматься до нуля, поэтому все семь остаются строго равными при любом содержимом. Это стандартный приём для «жёстких» сеток.

## 3.2 Автоматическая раскладка

Мы не задаём строки и позиции. Браузер размещает дочерние элементы **слева направо, перенося строку каждые 7 элементов** (авто-размещение). Поэтому порядок в DOM и есть порядок на экране:

```
[Пн][Вт][Ср][Чт][Пт][Сб][Вс]   ← первые 7 элементов: заголовки
[  ][  ][  ][ 1][ 2][ 3][ 4]   ← следующие 7: первая неделя (3 пустые клетки + 1,2,3,4)
[ 5][ 6]...                     ← и так далее
```

Именно поэтому нужны пустые клетки для чужих дней и `<template v-for>` без обёрток.

## 3.3 `aspect-ratio: 1`: квадраты без фиксированных размеров

Высота клетки равна её ширине, а ширина определяется колонкой. Календарь масштабируется вместе с карточкой месяца, жёстких пикселей нет. Для кнопки нужно ещё `padding: 0` и `font: inherit`, иначе браузерные стили по умолчанию сломают пропорции.

## 3.4 Абсолютное позиционирование внутри клетки

`.cell` имеет `position: relative`, поэтому вложенные `.cell__day` и `.cell__badge` с `position: absolute` позиционируются **относительно клетки**: число в левом верхнем углу, значок с количеством в правом нижнем. Их можно двигать независимо, не влияя на размеры клетки.

## 3.5 Состояния через классы

```css
.cell--high  { background: #fef2f2; }  .cell--high .cell__badge { background: #ef4444; }
.cell--alldone { opacity: 0.55; }
.cell--today { border: 2px solid #3b82f6; }
```

Цвет зависит от приоритета, прозрачность от завершённости, рамка от «сегодня». У правил одинаковая специфичность, поэтому важен **порядок**: правило, объявленное позже, выигрывает. `.cell--today` стоит последним, поэтому рамка сегодняшнего дня перебивает обычную. Так как кнопка использует `box-sizing: border-box`, утолщённая рамка не сдвигает соседние клетки.

## 3.6 Внешняя сетка из трёх месяцев

```css
.months-grid { display: grid; grid-template-columns: repeat(3, minmax(0, 1fr)); gap: 12px; align-items: start; }
@media (max-width: 1000px) { .months-grid { grid-template-columns: 1fr; } }
```

- Три равные колонки, по месяцу в каждой.
- `align-items: start` нужен потому, что месяцы бывают в 5 и в 6 недель. По умолчанию сетка растягивает карточки до одинаковой высоты, и у короткого месяца появилась бы пустая полоса снизу.
- На экранах уже 1000px действует медиазапрос: колонка остаётся одна, месяцы идут друг под другом. Такой же приём используется для недели (`.week-grid`: 7 колонок → 1).

Итого в `MonthCalendar` сетки вложены: внешняя (3 месяца) → карточка месяца → внутренняя (7 колонок × недели).

2. **Сгруппировать задачи по датам за один проход.** Сейчас `tasksForDates` фильтрует весь массив задач для каждого из ~100 дней в трёх месяцах: сложность «дни × задачи». На сотнях задач это незаметно, на тысячах начнёт тормозить. Один проход, который раскладывает задачи в `Map` по дате, даёт сложность «только задачи».

3. **Заменить ключ `wi` на `week[0].date`** во внешнем `v-for` недель. Индекс подходит для статичного списка, но дата стабильнее: при смене месяца Vue правильнее переиспользует и сопоставляет элементы, а риск странных артефактов при будущих изменениях исчезает.

4. **Показывать `error` из `useTasks` пользователю** (простое сообщение над списком). Сейчас ошибка сохраняется, но не видна. При переходе на бэкенд сетевые ошибки будут частыми, и без сообщения приложение будет выглядеть как «ничего не происходит».

5. **Не оставлять `read → изменить → write` на клиенте при переходе на сервер.** В `localStorage` две вкладки могут перезаписать друг друга (побеждает последняя запись), для учебного проекта это допустимо. С сервером используйте `PATCH` с изменением одного поля на стороне сервера, иначе одновременные правки с двух устройств будут терять данные.
